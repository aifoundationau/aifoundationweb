PART 2: HOW THE TOKEN SYSTEM WORKS (read before changing anything)
================================================================================

All the owner's apps share ONE Firebase project (ai-foundation-firebase) and
ONE token balance per person. Tokens bought in any app can be spent in any app.

BALANCE   users/{uid}.token_balance  (a whole number) on the person's shared
          profile. The LMS already uses this field. Only servers change it.

LEDGER    token_ledger/{entryId}: one entry for every change to a balance,
          written in the SAME atomic Firestore commit as the change. The entry
          ID is the change's own key, so the same change can never happen twice:
            purchase_<Stripe checkout session ID>
            grant_<request ID made once per SuperAdmin click>
            spend_<app tag>_<the app's own purchase ID>

PRICE     One price for every app, set by the owner in the AI Foundation admin
          panel: Services & Pricing -> Tokens -> "Price per token".
          Stored in system_settings/aifoundation_service_prices, field
          prices.tokens.perToken = { usd, aud }.
          - USD $1 per token when the USD box is blank.
          - Visitors in Australia pay the AUD price when one is set (typing a USD
            price fills the AUD box at today's rate, to the cent, e.g. 1.43).
            Everyone else pays USD.
          - Token prices keep their cents. (Other prices on the site are whole
            dollars.)

BUYING    Tokens are bought 10 at a time: the box starts at 10, + adds 10, - takes
          10 off, no upper limit (one request is capped at 1,000,000,000 to catch
          typing mistakes). Typed amounts must be multiples of 10 (15 rounds up to
          20). Payment is Stripe Checkout. The SERVER works out the price; the
          browser only says how many tokens. Card total must be 0.50 to
          999,999.99 (Stripe's limits).
          Tokens are added only after Stripe says the checkout is "paid": when
          Stripe sends the buyer back (POST /api/tokens/confirm), or, if they
          closed the tab, the next time they open Buy Tokens (unpaid checkouts are
          listed in token_checkouts/{appTag}_{uid} and rechecked).

SPENDING  POST /api/tokens/spend, or the token store's spendTokens() in your own
          server code. It never takes more than the balance (it reads the balance
          and only saves the lower amount if nothing changed it in between), and
          sending the same app + reference again never takes tokens twice.

TOP-UPS   SuperAdmins (only the two below) see "Token Accounts": every account in
          every app with its balance, and an add-tokens box (starts at 10, + adds
          10, no upper limit). Each top-up is a ledger entry.

PROFILE   Tokens live on the shared profile, so the app creates it on first
          sign-in (POST /api/profile/sync, called automatically by
          firebase-client.js). Existing profiles keep their balance and role.

RULES     firestore.rules is ONE file for the whole Firebase project (all apps).
          It lives in the AI Foundation project:
          E:\Antigravity Projects\ai-foundation\firestore.rules
          Never create or deploy a firestore.rules from the new app: deploying
          replaces the rules for every app.

FIXED VALUES (identical in every app; never change them)
  Firebase project ID ..... ai-foundation-firebase
  Balance ................. users/{uid}.token_balance (integer)
  Ledger .................. token_ledger/{entryId} (IDs above)
  Pending checkouts ....... token_checkouts/{appTag}_{uid}
  Token price ............. system_settings/aifoundation_service_prices,
                            prices.tokens.perToken {usd, aud}; default USD 1
  Token limits ............ min 10, step 10, priced per 1 token
  SuperAdmin UIDs ......... ZK79FRQoVlYhsgvMibhi81dRUWj2, L5euSJAfNKdDOX6mT0qmrCGjUA53
  SuperAdmin emails ....... davidrobertson.info@gmail.com, support@aifoundation.net.au
  Owner's domain .......... aifoundation.net.au
                            (aifoundation.com.au is NOT the owner's: never use it)
  App tags already in use . aifoundation, lms, rto-ai, pt, itsasimplejob, pro-lms
                            (choose a different one for the new app)

PART 5: SPENDING TOKENS IN YOUR APP (code examples)
================================================================================

Spend on the SERVER when tokens pay for something, so the price can't be changed
in the browser. The browser route POST /api/tokens/spend lets the signed-in user
choose the amount; use it only where the user decides the amount.

Server route (in the app's server file):

  const { attachUser, requireAuth } = require('./lib/auth');
  const { createTokenStore } = require('./lib/token-balances');

  // Made on first use, so a missing APP_TAG can't crash the server at startup
  let tokenStore = null;
  function tokens() {
      if (!tokenStore) tokenStore = createTokenStore({ appTag: process.env.APP_TAG, appName: process.env.APP_NAME });
      return tokenStore;
  }

  const COURSE_PRICE_TOKENS = 50;

  app.post('/api/courses/:id/buy', attachUser, requireAuth, async (req, res) => {
      try {
          const result = await tokens().spendTokens({
              uid: req.user.uid,
              tokens: COURSE_PRICE_TOKENS,
              app: process.env.APP_TAG,
              // The purchase's own ID: sending it again never takes tokens twice
              reference: `course-${req.params.id}-${req.user.uid}`,
              description: `Course ${req.params.id}`
          });
          if (result.status === 'insufficient') {
              return res.status(409).json({ error: 'Not enough tokens.', balance: result.balance });
          }
          // 'spent' or 'already-spent': give the user what they paid for here
          res.json({ ok: true, balance: result.balance });
      } catch (e) {
          console.error('[Course purchase]', e);
          res.status(500).json({ error: 'Tokens could not be spent just now, and none were taken.' });
      }
  });

Browser (where the user chooses the amount):

  const res = await fetch('/api/tokens/spend', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ tokens: 20, app: 'myapp', reference: 'tip-' + crypto.randomUUID(), description: 'Tip' })
  });
  const data = await res.json();
  // 200: { status: 'spent' | 'already-spent', spent, balance }
  // 409: { error: 'Not enough tokens.', balance }

Reading the balance: GET /api/tokens -> { balance, price, limits, canPay, isSuperAdmin, ... }

Rules for references: up to 100 characters from A-Z a-z 0-9 _ . : -
App tag in spends: the app's own tag (lower case).

PART 6: RULES ANTIGRAVITY MUST NEVER BREAK
================================================================================

 1. Nothing at the top level of a server file may throw when an environment
    variable is missing. Create clients (Stripe, token store) inside functions on
    first use. Missing settings pause one feature (answer 503); they never take
    the site down. Check with `npm run check:startup` before every push.
 2. Tokens are money. Change token_balance ONLY through lib/token-balances.js
    (ledger entry + balance change in one atomic commit; spends never below 0).
    Never write token_balance with a plain write, and never from a browser.
 3. The server works out every price. Never take an amount of money from the
    browser.
 4. firestore.rules is shared by every app and lives only in
    E:\Antigravity Projects\ai-foundation\firestore.rules. Never create or deploy
    rules from the new app. New Firestore collections must be added to
    isProtectedCollection there, or any signed-in user can read and write them.
 5. Do not change who is SuperAdmin unless the owner asks. The two SuperAdmins
    are in lib/auth.js and must match firestore.rules. The owner's domain is
    aifoundation.net.au; aifoundation.com.au is NOT theirs: never add it, or any
    address on it, anywhere.
 6. Keep public/token-pricing.js identical to AI Foundation's token rules (start
    10, step 10, price per token, USD $1 default, cents kept).
 7. Authorized sign-in domains: exact hostnames only, never plain vercel.app.
 8. New environment variables: add the name (never the value) to .env.example,
    and tell the owner to add it in Vercel, marking secrets Sensitive. Never
    commit .env or paste real keys into code.
 9. Before saying a change is done: run `npm test` and `npm run check:startup`
    and report the real output.
10. Do not commit or push unless the owner asks.


================================================================================
PART 7: TROUBLESHOOTING
================================================================================

Live site shows "500 FUNCTION_INVOCATION_FAILED"
  The server crashed while starting. Run `npm run check:startup`; it shows the
  error. Usually code at the top level needing a missing environment variable.

"Your account isn't fully set up yet"
  The shared profile wasn't created. Sign out and in again (that calls
  /api/profile/sync). If it keeps happening, the FIREBASE_CLIENT_EMAIL /
  FIREBASE_PRIVATE_KEY values are wrong or missing.

"Token balances can't be reached right now" / balance "Unavailable right now"
  The server can't sign in to Firestore. Check FIREBASE_CLIENT_EMAIL and
  FIREBASE_PRIVATE_KEY (whole key, \n for line breaks), then redeploy.

"Tokens are not set up on this server yet (APP_TAG is missing)"
  Set APP_TAG in .env / Vercel, then restart or redeploy.

"Card payments are not set up yet"
  STRIPE_SECRET_KEY is missing.

Sign-in popup error "auth/unauthorized-domain"
  Add the site's exact address to Firebase authorized domains (Step 6).

Paid, but no tokens
  Open the token page again while signed in: unpaid checkouts are rechecked and
  credited. Each purchase is in Stripe (metadata kind=tokens, uid, tokens) and,
  once credited, in token_ledger as purchase_<session ID>.

Firebase CLI: "Your credentials are no longer valid"
  Run `firebase login --reauth`, or paste the rules in the console (Step 7).

Rules deploy said "complete" but nothing changed
  Run it from the AI Foundation folder with --project ai-foundation-firebase, or
  publish in the console. Check: console -> Firestore -> Rules shows today's
  date.

Vercel CLI keeps asking for an email that never arrives
  Email login was removed (Feb 2026). Run `vercel login` with no email and
  approve in the browser, or use a token: https://vercel.com/account/tokens

Changes don't show in the browser
  Raise the ?v= number on the changed .js/.css file, then reload with Ctrl+F5.
